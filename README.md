# doctor-status-bot

Telegram-бот по Заданию 3: присылаешь фамилию врача — получаешь его текущий статус
(договор, курсы, сколько дней без активности, что известно из контекста).

## Как это устроено

```
bot.py     — Telegram-слой: приём сообщений, команды, отправка ответа
report.py  — логика: приоритет врача + «что делать дальше»
db.py      — SQLite: схема, данные из сводки и таблицы контекста
bot.db     — сама база (создаётся автоматически при первом запуске)
```

**База данных.** SQLite — один файл, никакого сервера поднимать не нужно.

| Таблица | Что хранит |
|---|---|
| `doctors` | ФИО, время последнего входа (`NULL` = не заходил ни разу) |
| `courses` | два курса и сколько всего назначено (33) |
| `enrollments` | кто на каком курсе: начал / прогресс / завершил / последняя активность |
| `context_notes` | таблица «Дополнительный контекст по врачам» из задания |
| `digest_headlines` | верхние строки сводки с числами (3 врача, 5%; 29 из 33, 88%) |

«N дней без активности» из сводки пересчитывается в абсолютное время:
`дата сводки (29.09, 09:00) − N часов`. Поэтому цифры в ответе бота совпадают со сводкой.

## Шаг 1. Получить токен у BotFather (3 минуты)

1. Откройте Telegram, найдите **@BotFather** (галочка верификации).
2. Отправьте `/newbot`.
3. Имя бота — любое, например `Статус врача`.
4. Username — обязательно заканчивается на `bot`, например `doctor_status_anna_bot`.
   Username должен быть свободен, иначе BotFather попросит другой.
5. BotFather пришлёт строку вида `7123456789:AAH...` — это `BOT_TOKEN`. **Никому не показывайте.**

Дополнительно (по желанию, но выглядит профессионально):
- `/setdescription` — описание бота;
- `/setuserpic` — аватар;
- `/setcommands` — меню команд. Отправьте одним сообщением:
  ```
  list - врачи, требующие внимания
  summary - полная сводка за день
  help - справка
  ```

## Шаг 2. Запустить локально и проверить

```bash
cd doctor-status-bot
python3 -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# откройте .env и вставьте свой токен в BOT_TOKEN=

python3 bot.py
```

В консоли появится `Бот запущен. Жду сообщения…`. Откройте своего бота в Telegram,
нажмите **Start** и напишите `Иванова`.

Проверить логику без Telegram (полезно, если что-то не сходится):

```bash
python3 db.py        # создаст и наполнит bot.db
python3 report.py    # распечатает карточки нескольких врачей в консоль
```

## Шаг 3. Выложить в интернет, чтобы бот работал круглосуточно

Локальный запуск выключается вместе с ноутбуком. Выберите один вариант.

### Вариант A. Render (минимум ручной работы)

1. Залейте папку в репозиторий на GitHub.
2. [render.com](https://render.com) → **New** → **Background Worker**
   (именно Worker, а не Web Service: у бота нет HTTP-порта, и Web Service будет ругаться на health check).
3. Подключите репозиторий. Настройки:
   - Build Command: `pip install -r requirements.txt`
   - Start Command: `python bot.py`
4. Вкладка **Environment** → **Add Environment Variable**:
   - `BOT_TOKEN` = ваш токен из шага 1
   - `DIGEST_DATE` = `2026-09-29`
5. **Create** → в логах должно появиться `Бот запущен`.

Учтите: Background Worker на Render — платный тип сервиса (у бесплатных
сервисов есть ограничение по «засыпанию» и типу). Уточните актуальные условия
тарифов на сайте перед выбором. Если бесплатный вариант нужен обязательно —
берите VPS или Railway (варианты B и C).

### Вариант B. Любой VPS с Docker

```bash
# на сервере
git clone <ваш-репозиторий> && cd doctor-status-bot
echo "BOT_TOKEN=7123456789:AAH..." > .env
mkdir -p /data
docker build -t doctor-bot .
docker run -d --name doctor-bot --restart unless-stopped \
  --env-file .env -v /data:/data doctor-bot
docker logs -f doctor-bot     # смотреть логи
```

### Вариант C. Railway (подробная инструкция — в файле RAILWAY.md)

Краткая версия: загрузить код на GitHub → railway.app → **+ New Project** →
**Deploy from GitHub repo** → выбрать репозиторий → задать переменные
`BOT_TOKEN` и `DB_PATH=/data/bot.db` → подключить Volume с путём `/data` → задеплоить.

Полный разбор с названиями кнопок, таблицей ошибок в логах и чек-листом проверки
лежит в **RAILWAY.md**. Важно: постоянного бесплатного тарифа у Railway нет —
есть стартовый кредит, дальше минимальный платный план.

### Хранение базы

Файл `bot.db` создаётся при первом запуске и наполняется данными из `db.py`.
На бесплатных тарифах файловая система часто эфемерная — после перезапуска база
пересоздастся из кода, и это нормально: данные в `db.py` те же, что в сводке.
Если планируете дописывать данные через бота — подключите постоянный диск
и задайте `DB_PATH=/data/bot.db`.

Отдельно про `RESET_DB`: если база уже лежит на постоянном диске, правки в `db.py`
не доедут до неё автоматически — `init_db` не перезаписывает существующую базу.
Чтобы подтянуть новые данные, задайте переменную `RESET_DB=1`, перезапустите сервис,
дождитесь в логе строки `RESET_DB=1 → база пересоздана с нуля`, а затем уберите
переменную или поставьте `RESET_DB=0`. Подробнее — в RAILWAY.md, шаг 8.
