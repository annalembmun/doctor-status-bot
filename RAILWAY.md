# Деплой на Railway — пошагово

Railway запускает ваш код в контейнере. Проект уже подготовлен: есть `Dockerfile`,
`.dockerignore`, база вынесена на постоянный диск.

**Итого по времени:** 20–30 минут, из них 15 — на регистрацию и ожидание сборки.

---

## Шаг 0. Что должно быть готово ДО Railway

- [ ] Токен от **@BotFather** (строка вида `7123456789:AAH...`)
- [ ] Аккаунт на **GitHub** (Railway умеет брать код и с GitHub, и с локальной машины,
      но с GitHub заметно удобнее передеплоить потом)
- [ ] Папка `doctor-status-bot` целиком — 9 файлов

Проверьте состав папки. Здесь **не должно** быть `.env` и `bot.db`
(они в `.gitignore` и `.dockerignore`). Должно быть ровно это:

```
doctor-status-bot/
├── bot.py              ← код бота
├── db.py               ← база: схема + данные из сводки
├── report.py           ← логика статуса врача
├── requirements.txt    ← библиотеки
├── Dockerfile          ← инструкция сборки для Railway
├── .dockerignore       ← что не тащить в образ
├── .env.example        ← образец переменных (не настоящий токен!)
├── .gitignore          ← что не грузить на GitHub
└── README.md, RAILWAY.md
```

## Шаг 1. Создать репозиторий на GitHub

Railway будет забирать код именно отсюда.

1. Откройте **github.com**, войдите в аккаунт (или создайте — это бесплатно).
2. Справа сверху — **«+»** → в выпадающем меню **New repository**.
3. Заполните:
   - **Repository name:** `doctor-status-bot`
   - **Description:** можно оставить пустым
   - **Public** — отметить (так проще показать ссылку в задании)
   - Пункты «Add a README file», «Add .gitignore», «Choose a license» —
     **оставьте снятыми**, иначе GitHub создаст лишние файлы и будет конфликт.
4. Кнопка **Create repository** (репозиторий создастся пустым).
5. На открывшейся странице будет блок «…or push an existing repository from the command line» —
   он нам и нужен, но команды удобнее взять из шага 2.

**Если не хочется возиться с git в терминале**, можно просто:
на странице пустого репозитория нажать **uploading an existing file** →
перетащить все 9 файлов мышкой → внизу нажать **Commit changes**.
Railway такое устроит. Только не перетаскивайте `.env` и `bot.db` — это лишнее и небезопасно.

### Вариант через терминал (git)

```bash
cd doctor-status-bot
git init
git add .
git commit -m "Бот статуса врача: Задание 3"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/doctor-status-bot.git
git push -u origin main
```

Если git попросит пароль — нужен не пароль от GitHub, а **Personal Access Token**:
GitHub → правый верхний угол, аватар → **Settings** → в самом низу **Developer settings** →
**Personal access tokens** → **Tokens (classic)** → **Generate new token (classic)** →
отметить галочку `repo` → **Generate** → скопировать и вставить вместо пароля.

## Шаг 2. Завести аккаунт на Railway

1. Откройте **railway.app**.
2. Кнопка **Login** (или **Start a New Project**) справа сверху.
3. Выберите **Login with GitHub** — так Railway сразу получит доступ к вашим репозиториям.
4. GitHub спросит разрешение — нажмите **Authorize Railway**.
   Можно сразу дать доступ ко всем репозиториям или только к нужному.
5. Railway попросит подтвердить аккаунт. Здесь важно понимать механику:
   у Railway нет постоянного бесплатного тарифа — новому аккаунту дают небольшой
   стартовый кредит (обычно $5), и на нём проект живёт ограниченное время.
   Чтобы сервис не отключился, придётся привязать карту и перейти на минимальный
   платный план (порядка $5/мес). Условия и суммы Railway меняет, поэтому
   сверьтесь с актуальной страницей **Pricing** на их сайте перед стартом —
   возможно, для учебного тестового найдёте вариант выгоднее.

   Хорошая новость: сам бот почти не потребляет ресурсов, и на минимальном
   плане он укладывается в копейки. Плохая: если платить не хочется совсем,
   Railway — не лучший выбор, тогда берите VPS (вариант B в README).

## Шаг 3. Создать проект и подключить репозиторий

Названия кнопок Railway периодически меняет — если не найдёте точь-в-точь,
ищите кнопку со смыслом «новый проект» и пункт про GitHub.

1. На главной Railway (railway.app/dashboard) нажмите **+ New Project**.
2. В меню выберите **Deploy from GitHub repo** (может называться **GitHub Repo**).
3. Railway покажет список ваших репозиториев. Нажмите на **doctor-status-bot**.
   - Если списка нет — нажмите **Configure GitHub App** и выдайте Railway доступ
     к этому репозиторию, потом вернитесь и обновите страницу.
4. Появится выбор: **Deploy Now** или **Add variables**.
   Выбирайте **Add variables** — переменные нужно задать ДО первого запуска,
   иначе контейнер упадёт с ошибкой «Не задан BOT_TOKEN».

---

## Шаг 4. Задать переменные окружения (самый важный шаг)

Откроется окно с переменными (если закрыли — вкладка **Variables** в сервисе).

Нажимайте **+ New Variable** и добавьте по одной:

| Variable Name | Value | Обязательно |
|---|---|---|
| `BOT_TOKEN` | `7123456789:AAH...` (ваш токен от BotFather) | **да** |
| `DIGEST_DATE` | `2026-09-29` | да |
| `DB_PATH` | `/data/bot.db` | да |

Правила, на которых легко споткнуться:
- имя переменной — **ровно** `BOT_TOKEN`, без пробелов и кавычек;
- значение вставляйте **без кавычек** и без слова `BOT_TOKEN=` — только сам токен;
- в токене есть двоеточие — это нормально, ничего не обрезайте;
- переменную `DB_PATH` со значением `/data/bot.db` лучше задать сразу: тогда база
  ляжет на диск из шага 6, а не внутрь контейнера.

После добавления трёх переменных нажмите **Deploy** (или **Deploy Now**).

---

## Шаг 5. Подключить постоянный диск (Volume)

Без него база живёт внутри контейнера и обнуляется при каждой пересборке.

1. В сервисе откройте вкладку **Volumes** (иногда называется **Settings → Volumes**).
2. Нажмите **+ Add Volume** / **New Volume**.
3. **Mount path** — впишите ровно: `/data`
   (именно такой, потому что в `DB_PATH` стоит `/data/bot.db`; если пути не совпадут,
   база окажется вне диска и снова будет теряться).
4. **Save**. Railway перезапустит сервис — это нормально.

Если решите обойтись без диска — тогда уберите переменную `DB_PATH`, и база создастся
рядом с кодом внутри контейнера. Бот будет работать и отвечать, просто данные
пересоздадутся из `db.py` при следующем деплое. Для сдачи задания это допустимо:
данные всё равно вшиты в код.

## Шаг 6. Проверить, что всё поднялось

1. Откройте сервис → вкладка **Deployments** (или **Deploy Logs**).
2. Смотрите лог. Сборка идёт 1–3 минуты, вы увидите примерно:

```
📦 Building...
Step 1/8 : FROM python:3.12-slim
...
Successfully built
🚀 Starting Container
2026-10-01 ... | INFO | doctor-status-bot | База готова: /data/bot.db
2026-10-01 ... | INFO | doctor-status-bot | Бот запущен. Жду сообщения…
```

Последняя строка `Бот запущен. Жду сообщения…` — значит всё работает.

### Если в логах ошибка

| Что написано в логе | Причина и что делать |
|---|---|
| `Не задан BOT_TOKEN` | переменная не сохранилась или опечатка в имени. Variables → проверить, что имя ровно `BOT_TOKEN`, затем **Redeploy** |
| `ModuleNotFoundError: No module named 'telegram'` | сборка прошла по старому кэшу. **Deployments → ⋯ → Redeploy** с галочкой «Clear build cache» |
| `Incorrect token format` / `Unauthorized` | токен скопирован не полностью или с лишним пробелом. Взять заново у @BotFather и вставить целиком |
| `Conflict: terminated by other getUpdates request` | одновременно запущены две копии бота (например, ещё крутится локально). Остановите локальный запуск — Telegram разрешает только один polling на токен |
| Сервис перезапускается по кругу | смотрите лог целиком, ключевая строка обычно в самом конце |

## Шаг 7. Проверить бота в Telegram

1. Откройте Telegram, найдите своего бота по тому username, что задали BotFather.
2. Нажмите **Start**.
3. Проверьте по чек-листу:
   - `/start` → приходит приветствие со списком команд
   - `Иванова` → 🔴 критично, 51 дн 18 ч, пауза после операции
   - `Смирнов` → 🟠 высокий, договор подписан, курс не начат
   - `Козлов` → 🟠 высокий, нет связи с 20 июня
   - `петров петр` → находит Петрова (поиск понимает ё/е и имя без фамилии)
   - `/list` → сводка с числом врачей и процентами
   - `Абракадабра` → вежливое «не нашёл», бот не падает

Если всё зелёное — копируйте ссылку `https://t.me/ваш_бот` и отправляйте в задании.

## Шаг 8. Что делать потом (если понадобится правка)

**Поменяли данные в `db.py`** (например, добавили врача):

1. Залейте изменения на GitHub (`git add . && git commit -m "..." && git push`).
2. Railway увидит пуш и пересоберёт сервис **автоматически**.
3. Важный нюанс: если база уже лежит на диске, старые данные там останутся —
   `init_db` не перезаписывает существующую базу. Чтобы подтянуть новые данные:
   в **Variables** добавьте `RESET_DB` = `1` → **Redeploy** → дождитесь
   строки в логе `RESET_DB=1 → база пересоздана с нуля` → затем **удалите**
   переменную `RESET_DB` или поставьте `0`, и ещё раз **Redeploy**.
   Если забыть убрать флаг, база будет пересоздаваться при каждом перезапуске.

**Кончился пробный период:** Railway начнёт ограничивать сервис. Варианты —
пополнить баланс (бот стоит копейки, он почти не потребляет ресурсов)
или перенести проект на вариант с Docker с VPS, он описан в README.

## Частые затыки и короткие ответы

**Не вижу репозиторий в списке Railway** → Configure GitHub App → дать доступ к репозиторию.

**Сервис собрался, но бот молчит** → почти всегда проблема с токеном:
проверьте, что запущена ровно одна копия бота и токен полный.

**Хочу проверить логи ещё раз** → сервис → **Deployments** → нажать на активный
деплой → справа **View Logs**.

**Хочу поменять токен** → Variables → изменить `BOT_TOKEN` → Redeploy.
Отдельный токен при этом создавать не нужно, старый продолжит работать.

**Важно про безопасность:** реальный `.env` и `bot.db` на GitHub не загружайте.
Если токен всё-таки утёк — отзовите его у BotFather командой `/revoke`
и выпустите новый, иначе ботом сможет управлять любой.
